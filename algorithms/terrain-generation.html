절차적 지형 생성

FastNoise를 재료로 쓰되, 게임의 통행·충돌·재현성까지 별도로 완성하는 실전 레퍼런스.

1.개요 · 노이즈와 게임 지형의 경계

노이즈는 좌표마다 연속적인 값을 만드는 재료다. FastNoise를 연결했다고 안전한 시작점, 길, 충돌, 적 배치까지 완성되는 것은 아니다. 플레이 규칙을 먼저 정하고 노이즈를 그 안에서 사용한다.

출처를 정확히 부르기
Jordan Peck의 개인 홈페이지에는 자신을 Hello Games에서 No Man’s Sky를 개발하는 프로그래머로 소개한다. 그러나 FastNoise Lite와 FastNoise2는 Auburn 계정의 공개 노이즈 라이브러리다. 이를 Hello Games가 공식 공개한 지형 엔진, 또는 No Man’s Sky 전체 월드 생성 코드로 소개하지 않는다.

이 문서의 통행 폭·스폰·캐시·파이프라인은 BLOOM의 적용 설계 제안이다. 라이브러리의 보장 사항과 구분한다. 아직 특정 게임에 적용·검증한 결과가 아니며, 예제 숫자는 시작점이지 합격 기준이나 성능 실측값이 아니다.

  • 높이장(heightfield): 평면 좌표마다 높이 하나. 2.5D 언덕에는 적합하지만 한 위치에 동굴 바닥과 천장을 함께 표현하기 어렵다.
  • 밀도장(density field): 3차원 좌표마다 고체/빈 공간을 판정할 값. 동굴·돌출부를 표현할 수 있지만 표면 추출과 충돌 구축이 추가된다.
  • 게임 지형: 높이/밀도 + 지역 의미 + 통행 규칙 + 구조물 + 스폰 + 검증 + 저장 형식이다.

2.게임 유형별 선택 가이드

아래 네 열은 권장 방식 → 가져올 기능 → 별도 구현 → 검증 순서다. 작고 고정된 맵에 청크·복잡한 노드 그래프부터 도입하지 않는다.

서브셋 사용의 의미
공식 라이브러리를 의존성으로 고정하고 필요한 설정·API만 래퍼에 노출한다. 내부 함수 일부를 복사해 별도 미니 포크를 만드는 뜻이 아니다. 배포한 소스의 라이선스 고지와 사용 버전/커밋을 보존한다.

3.핵심 기법 · 무엇을 어떻게 조합하는가

비용 표기는 샘플 수 N, 옥타브 수 O, 혼합 지역 수 B를 기준으로 한 설계상 근사다. 노이즈 종류·언어·CPU/GPU에 따른 상수와 메시·충돌 생성 비용은 별도 측정한다.

기법 · 목적 / 동작주요 조절값비용 · 확인할 점 · 1차 출처
기본 노이즈
좌표를 매끄러운 값으로 바꿔 큰 지형 덩어리와 재질 변화를 만든다. 각 칸을 독립 난수로 채우는 방식과 다르다.		seed, noise type, frequency, 출력 높이 배율대략 O(N). 주파수가 높으면 작은 패턴이 많아진다. 타일 해상도에서 앨리어싱·반복감·방향성 확인. GetNoise 문서

마스크
0~1 가중치로 섬 가장자리·길·스폰 주변 등 효과를 적용할 범위를 제한한다. 거리장·수작업 영역·노이즈 임계값 등을 조합한다.		거리, threshold, falloff 폭, 보호 반경, remap curve단순 마스크 합성은 O(N), 거리장 구축은 별도. 순서가 바뀌면 보호 영역에 장애물이 다시 생길 수 있다. 노이즈 임계값을 전체 장애물 비율 보장으로 오해하지 않는다. 공식 Multiply·Remap 연산을 활용한 적용 설계
지역 블렌딩
초원·산악 등 서로 다른 생성 규칙을 지역 가중치로 섞는다. height = Σ(weight × height) / Σweight. 지역 분류와 부드러운 경계는 별개다.		지역 필드 주파수, 경계 폭, 가중치 정규화, 지역별 높이·밀도모두 평가하면 O(NB), 각 필드 옥타브 비용 추가. 가중치 합 0의 fallback, 경계 경사·재질·충돌 일치 검사. 공식 Blend·Fade 연산을 활용한 적용 설계

마스크와 지역 블렌딩은 라이브러리가 게임 규칙까지 자동 제공한다는 뜻이 아니다. 같은 이름의 옵션이라도 포트·버전별 정확한 API와 enum 이름은 고정한 소스에서 확인한다.

4.생성 파이프라인 · 한 지형 데이터의 여러 표현

계약·설정→필드 샘플링→지역·마스크 합성→통행 구조 확정→배치·검증→캐시·표현
  1. 게임 계약: 최소 통행 폭, 캐릭터 반경, 허용 경사, 시작점과 목표, 맵 규모부터 정한다.
  2. 필드: 월드 좌표로 높이/밀도·지역 가중치를 계산한다. warp를 사용하면 좌표계와 적용 순서를 고정한다.
  3. 구조: 플레이 공간과 보호 마스크를 적용하고 필요하면 길·다리·터널을 명시적으로 연결한다. 연결 보정은 노이즈 라이브러리 밖의 게임 로직이다.
  4. 배치: 충돌 반경과 스폰 보호 구역을 지키며 장애물·콘텐츠를 배치한다. 외형만 바꾸는 장식은 통행을 바꾸지 않는다.
  5. 검증: 최종 충돌 데이터 기준으로 이동 가능 영역·출입구·목표 도달을 검사한다. 실패 시 결정론적 보정 또는 제한된 재시도 후 알려진 안전 맵으로 대체한다.
  6. 공유: 검증 완료 TerrainData를 renderer·collision·minimap이 읽는다. 각각 다시 노이즈를 호출해 따로 지형을 만들지 않는다. 표현 LOD가 달라도 지형 식별자·좌표·경계 규칙은 같다.
TerrainData = {
  identity, bounds, cellSize,
  heightOrDensity, regionIds,
  walkability, spawnPoints, modifications
}
render(TerrainData)
collision(TerrainData)
minimap(TerrainData)

검증 실패를 무제한 seed 재추첨으로 숨기지 않는다. 원 seed·실패 이유·시도 번호·생성기 버전을 남기고, 같은 입력에서 같은 보정과 fallback이 선택되게 한다.

5.설정 예제 · 실행 코드와 계약을 구분

다음은 작은 2.5D 맵용 프로젝트 설정 스키마 예시다. FastNoise Lite에 그대로 전달하는 공식 API 코드가 아니다. 숫자는 월드 단위와 실제 이동체 크기에 맞춰 조정하며 라이브러리 버전은 설치한 정확한 태그/커밋으로 채운다.

{
  "seed": 42017,
  "generatorVersion": "terrain-v1",
  "libraryRevision": "PIN_EXACT_TAG_OR_COMMIT",
  "coordinates": { "unit": "world-unit", "cellSize": 1 },
  "height": {
    "noiseType": "OpenSimplex2", "frequency": 0.02,
    "fractal": "FBm", "octaves": 3,
    "lacunarity": 2.0, "gain": 0.5, "heightScale": 4
  },
  "warp": { "enabled": false, "amplitude": 1 },
  "playability": { "agentRadius": 0.4, "minCorridorWidth": 2,
                   "spawnClearanceRadius": 5 },
  "chunks": { "enabled": false },
  "cache": { "maxBytes": 16777216 }
}
래퍼의 책임
설정 유효성 확인 → seed/좌표 규약 고정 → 공식 API에 명시적으로 매핑 → 샘플 → 출력 범위 재매핑 → 플레이 규칙 적용. 숨은 기본값에 의존하지 않는다. 설정 변경 시 canonical config hash를 갱신한다.
// 언어 중립 의사코드: 공식 API 이름을 보장하지 않음
base = makePinnedNoise(config.height, deriveSeed(seed, "height"))
warp = makePinnedWarp(config.warp, deriveSeed(seed, "warp"))
for each worldPosition p:
    q = config.warp.enabled ? warpPosition(warp, p) : p
    h = sample(base, q) * config.height.heightScale
    terrain[p] = blendRegionsAndApplyMasks(p, h)
finalizePlaySpace(terrain, config.playability)
validateOrDeterministicallyRepair(terrain)
publishTerrainData(terrain)

deriveSeed의 문자열 해시·정수 범위도 고정한다. 콘텐츠 배치용 PRNG와 지형용 seed를 구분하면 장식 하나를 추가했다고 전체 지형이나 스폰 순서가 바뀌는 일을 줄일 수 있다.

6.결정론 · 청크 · 캐시

6.1 seed 하나로는 부족하다

seed + generatorVersion + libraryRevision + 정규화한 config + 좌표 규약을 재생성 계약으로 저장한다. 청크를 사용하면 청크 좌표·해상도·LOD·변경분 버전도 식별에 포함한다. 동일 seed라도 알고리즘·설정·샘플 좌표가 바뀌면 다른 지형이다.

  • 샘플 순서와 스레드 완료 순서에 영향받지 않게 월드 좌표 기반으로 계산한다. 순차 PRNG를 쓰는 배치 단계는 순서도 고정한다.
  • JS·GLSL·네이티브가 같은 seed를 받는다고 부동소수점 비트 단위 일치가 자동 보장되지 않는다. 임계값 주변과 경계 좌표를 golden sample로 비교한다.
  • 네트워크/리플레이가 엄격한 동일성을 요구하면 권위 있는 지형 데이터를 공유하거나 고정 구현·양자화 규약을 정한다. 저장 맵을 새 생성기로 조용히 다시 만들지 않는다.

6.2 청크는 규모가 요구할 때

각 청크의 로컬 좌표가 아니라 world = chunkOrigin + local로 샘플링한다. 음수 좌표의 floor 규약, 경계 공유 샘플, 노멀·충돌용 여유 샘플(halo), LOD 이음 처리를 정한다. 플레이어가 빨리 이동할 때 작업 취소·우선순위·동시 생성 수를 제한한다.

6.3 캐시 키와 무효화

key = hash(seed, generatorVersion, libraryRevision, configHash,
           coordinateConvention, chunkCoordinates, resolution,
           lod, modificationVersion)

캐시는 항목 수뿐 아니라 실제 바이트 상한을 둔다. 생성 필드·메시·충돌체의 수명을 구분하고, 변경된 청크와 영향을 받는 이웃만 무효화한다. 사용자가 바꾼 지형의 변경분은 재생성 가능한 기본 지형 캐시와 분리해 보존한다.

관련 알고리즘: Seeded PRNG · Deterministic Simulation · Cache Invalidation · Bounded Cache.

Connected Components로 접근 가능 영역을 확인하되 높이·점프·경사·문 같은 실제 이동 규칙을 그래프에 반영한다. NavMesh는 금지 대상이 아니다. 맵과 에이전트에 적합하면 사용하고, 동적 지형은 국소 NavMesh 갱신 비용을 따로 측정한다.

성능 개선 순서는 불필요한 생성 제거 → 해상도/옥타브 축소 → 재사용/캐시 → 필요할 때 청크·배치·SIMD다. 단일 노이즈 벤치마크를 전체 게임의 성능 보장으로 쓰지 않는다.

게임 수치 계약은 스탯·수치 설계, 시인성·플레이 피드백은 비주얼·UX 기준과 함께 검토한다.

8.출처 · 관련 문서

공식 1차 자료 확인일: 2026-10-10. 라이브러리 기능 설명은 아래 문서에 근거하며, 파이프라인·캐시·게임 검증은 이를 사용하기 위한 적용 제안이다.
