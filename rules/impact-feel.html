0. 타격감의 기준과 투자 순서

타격감은 내 행동 → 실제 접촉 → 상대와 세계의 반응을 짧고 분명하게 읽는 경험이다. 파티클 양보다 입력의 신뢰, 접점, 시간 대비와 결과의 일치가 먼저다. 이 문서는 기법을 고르는 종합 진입점이며, 상세 시각 실험·알고리즘 원문은 기존 문서로 연결한다.

대표 best practice는 바운코
사용자가 고른 기준은 바운코다. 아래는 최신 확인 커밋의 구현 사실과 다른 게임에 적용할 설계 제안을 구별한다. 체감 우선순위는 실험 출발점이며 사용자 연구로 입증된 보편 순위가 아니다.
  1. 먼저 · 높은 체감 / 낮음~중간 비용: 입력 누락·불필요한 잠금, 접점/방향 불일치를 고친다. 실제 명중에 짧은 국소 hitflash와 충격음을 맞춘다. 기존 상태·오디오 경로가 있다면 자산 추가보다 저렴하다.
  2. 다음 · 높은 체감 / 중간 비용: 준비와 발사 반동, squash 복원, 피격 impulse를 조합한다. 물리·판정에 영향을 주면 구현/검증 비용도 함께 커진다.
  3. 조건부 · 중간~높은 비용: hitstop·입력 유예·버퍼·연쇄 시간표. 게임 리듬과 멀티 계약까지 정하고 도입한다. 이미 반응이 좋은 게임은 정지를 추가하지 않아도 된다.
  4. 마지막 · 비용 증가 대비 체감이 쉽게 포화: 카메라 흔들림, 큰 폭발, 긴 잔상, 후처리. 밀집 전투·효과 축소에서 의미가 유지될 때만 보강한다.

게임별 선택: 묵직한 근접전은 접촉 자세와 짧은 정지가 유효할 수 있다. 연사·지속 빔은 매 타격 정지보다 소리·국소 펄스·지속 흔적이 읽기 쉽다. 정밀 플랫폼은 점프 유예·버퍼가, 대규모 전투는 국소 반응과 정보 밀도 제한이 먼저다. 경쟁전에서는 서로 합의한 규칙과 예측 정정 비용을 함께 고려한다.

1. 예고·준비 → 행동을 예상하게 한다

예고와 차징

목적 · 언제 공격 방향·범위·실행 시점을 미리 읽게 한다. 위험 공격, 모아 쏘기, 회피 가능한 큰 기술에 쓴다. 즉발 행동에 준비를 억지로 넣지 않는다.

과용·실패 상시 빛남·긴 준비로 조작이 둔해지거나, 실제 취소/대상 이동과 예고가 다르게 남는다.

조절변수 준비 시간, 실루엣 변화, 범위/방향 고정 시점, 차지 단계, 취소 복원 시간.

예제·원리 P8 상태별 계약 · 스케치 전투의 준비/공격 비교

예고는 공격 성공을 보장하는 표시가 아니다. 준비·활성·회복 상태가 판정의 원본이며, 취소·기절·대상 소실 때 예고도 같은 사건으로 끝낸다. 준비 중의 작은 입력 확인과 실제 성공 피드백의 강도를 나눈다.

2. 발사·반동 → 힘이 출발하는 순간

발사 반동과 분출

목적 · 언제 발사가 실제로 실행된 시점과 힘의 반대 방향을 전달한다. 투사체 생성, 총구·공전 탄 출발, 돌진 시작처럼 명확한 성공 사건에 쓴다.

과용·실패 버튼마다 반동·탄 소비를 실행하거나, 렌더마다 impulse를 다시 주거나, 감쇠 종료가 전진 속도까지 지운다.

조절변수 반동 속도/impulse와 단위, 감쇠, 최대 지속시간, 출발 접점, 꼬리 수명, 취소 시 잔여 속도 정리. 충돌 solver가 속도를 바꾼 뒤 이전 반동을 복원하지 않는다.

예제·원리 바운코 공전 탄 정렬·발사와 반동 · createShadow / updateLaunchRecoil

바운코 구현 사실: 준비 탄이 기본 80ms 정렬한 궤도 위치에서 실제 잔상이 되며, 성공 사건에 반대 방향 45px/s 반동과 짧은 눌림·뒤쪽 분출을 연결한다. 전투 속도와 잔여 반동 성분을 분리한다. 이는 바운코의 크기·속도·물리에 맞춘 설정이다.

3. 접촉 → 판정과 보이는 접점을 맞춘다

판정·접점·방향의 일치

목적 · 언제 무엇이 어디에 맞았는지 납득시킨다. 모든 타격의 기반이다. 빠른 돌진/투사체는 한 틱 사이 통과와 높이 분리도 확인한다.

과용·실패 피해는 안 났는데 성공 숫자가 뜨거나, 빔과 판정 방향이 다르거나, 접촉 반대편에서 폭발한다. 눈속임으로 판정 오류를 덮지 않는다.

조절변수 충돌/스윕 결과, 법선, 접촉 위치, 피해 허용/방어/무적/중복 판정, 빔 두께와 높이, 렌더 보간 지연.

예제·원리 바운코 handleCollision / sweepDashContact · 레이저가 공유하는 빔 상태와 XYZ 접촉

효과 위치는 가능한 실제 충돌 결과를 재사용한다. 두 중심의 중간점 같은 근사는 큰 물체·긴 무기에서 어긋날 수 있으므로 화면으로 검토한다. 바운코 일반 돌진의 충격파는 중심 중간점을 사용한다. 레퍼런스의 강점을 가져와도 근사를 모든 게임의 접점 해법으로 복사하지 않는다.

Hitflash · 국소 명중 섬광

목적 · 언제 표적에 순간적인 대비를 만들어 명중 시점을 알린다. 빠른 적중, 작은 적, 피해와 방어 성공을 구분할 때 쓴다.

과용·실패 매 타격마다 전신 백색·전체 화면 점멸이 겹쳐 외형·다음 예고를 가리고 피로를 준다. 색 하나로만 성공을 구분한다.

조절변수 대상/접점 범위, 색·명도, 지속시간, 중첩 시 갱신/상한, 무적·방어 반응과 구분.

예제·원리 파티클 연구소의 충격/광원 계열 · 전투 중 국소 명중 예제

Squash · 압축과 복원

목적 · 언제 딱딱한 좌표 이동에 탄성과 질감을 더한다. 물렁한 캐릭터, 발사 압축, 접촉/착지 반응에 쓴다.

과용·실패 연타마다 스케일을 곱해 몸이 찌그러진 채 남거나, 그림자/피격 경계까지 변해 실제 판정을 오해한다.

조절변수 충격 방향 축, 압축 비율, 복원 곡선/감쇠, 최대 변형, 중첩 우선순위, 리셋 경계. 외형만 변할지 collider도 변할지 명시한다.

예제·원리 바운코 씨앗 플레이어의 충돌 압축·지연 흔들림 · A063 시간선 재타기팅

Hitstop · 짧은 멈춤으로 접촉을 읽힌다

목적 · 언제 이동 대비를 만들어 타격 자세와 무게를 강조한다. 강한 근접 접촉·마무리 등 리듬상 쉼이 필요한 사건에 선택한다.

과용·실패 지속 빔/연타마다 누적해 조작이 끊기거나, 시간이 멈춘 화면에서 판정은 지나가 불공정하게 느껴진다.

조절변수 게임 규칙/표현 전용, 공격자·피격자·세계 범위, 남은 tick 또는 표시 ms, 중첩 상한/최대값/연장 정책, 정지 중 각 시계 정책.

예제·원리 멀티 hitstop 계약 · 바운코의 서로 다른 정지 설정

충격음 · 접촉의 시간 표식

목적 · 언제 짧은 시작음과 잔향으로 재질·힘·성공 여부를 보완한다. 명중·막힘·치명타를 분리하고 시각을 보지 못하는 순간에도 사건을 알려 줄 때 쓴다.

과용·실패 모든 적중에 최대 음량/같은 고음을 겹치거나 소리만으로 필수 판정을 전달한다. 재시뮬마다 다시 재생한다.

조절변수 attack/decay, 피치 변이 범위, 재질 레이어, 동시 voice 상한, 거리/우선순위, 믹스 여유, 예측/확정 정책.

예제·원리 소리 중복·취소 정책 · 연쇄 시각·오디오·시간

4. 피격 반응 → 맞은 뒤의 결과를 보여 준다

Impulse · 순간 운동량 변화

목적 · 언제 힘이 실제 이동으로 전달되게 한다. 물리 접촉·발사 반동·짧은 밀림처럼 이후 운동은 물리 solver에 맡길 때 쓴다.

과용·실패 질량·단위를 무시하고 force와 혼용하거나, 매 프레임 재적용해 계속 가속한다.

조절변수 impulse 크기/방향, 질량 적용 여부, 속도 상한, 마찰·감쇠, 벽 충돌/기존 속도와 합성.

예제·원리 바운코 applyImpulse / impactPush

Stun · 행동 제약

목적 · 언제 맞은 결과로 행동 가능 시간이 달라짐을 읽게 한다. 공격 끊기·경직·콤보 개입을 게임 규칙으로 의도할 때 쓴다.

과용·실패 시각 흔들림을 실제 경직으로 오해하게 하거나, 모든 연타가 무한 경직을 만든다.

조절변수 지속 tick, 중첩/면역/저항, 이동·공격·입력 예약 중 무엇을 막는지, 해제/복구 경계.

예제·원리 상호 배타 상태와 독립 상태 · 경직·정지의 복원 계약

Knockback · 의도한 밀려남

목적 · 언제 방향·거리·회복 구간으로 공격 결과와 다음 전장을 만든다. 거리 벌리기, 벽 충돌, 무거운 적과 가벼운 적의 차이를 설계할 때 쓴다.

과용·실패 모든 적을 멀리 날려 다음 공격이 빗나가거나 장애물을 통과한다. 피해량과 무조건 비례시켜 작은 공격이 무력화된다.

조절변수 시작 속도/impulse 또는 이동 곡선, 거리, 제어권 회복, 벽/높이 제약, 저항/질량, 여러 공격 동시 합성.

예제·원리 바운코 왕사슴의 특수 넉백과 실제 접근속도 피해 · 연쇄 중 개입과 조작

구분: impulse는 운동을 바꾸는 수단, knockback은 밀려남의 게임 규칙/경험, stun은 행동 제약이다. 셋을 같은 timer로 취급하지 않는다. 외형 흔들림만으로 피격을 표현할 수도 있고, 밀려나면서도 입력은 허용할 수 있다.

5. 연쇄 리듬·마무리 → 작은 적중과 큰 종결을 구분한다

연타의 간격과 강약

목적 · 언제 원인과 다음 타격의 연결을 읽고 마지막 결과를 느끼게 한다. 자동 후속 공격, 도탄, 콤보, 광역 다중 명중에 쓴다.

과용·실패 모든 타격을 마무리처럼 크게 처리해 대비가 사라지거나 숫자를 한 번으로 합쳐 개별 적중 리듬을 지운다.

조절변수 타격 간격, 준비/발사/접촉/회복 시간표, 강타 조건, 오디오 피치/레이어 상한, 잔상 수명, 동시 적중 우선순위.

예제·원리 기존 연쇄 시간·시각·오디오 원문 · 혼잡 전투와 연타 숫자

마무리는 처치·콤보 종료·특수 방어 파괴 등 실제 사건에만 연결한다. 끝났는데 다음 공격이 남아 있으면 잘못된 신호다. 연쇄 중 수동 취소·대상 소실·탄 부족도 정상적인 종료로 읽히게 한다.

  • 접촉과 결과: 실제 양수 피해의 돌진 충돌에서 명중·콤보·충격음·충격파·후속 대상 준비를 묶는다. 레이저는 표시와 판정이 같은 빔 상태를 읽는다.
  • 강약의 차이: 일반 돌진 명중 C.timing.hitstopMs=50, 그림자 도착 shadowHitstopMs=50. 스킬 연쇄 가속 release의 첫 유효 impact마다 45ms, 탄성 폭발 release의 첫 유효 impact 65ms다. 레이저 연타에는 hitstop이 없다. impactShown이 같은 단계에서의 재발동을 막는다. 45/65ms는 일반 명중 기본값이 아니다.
  • 시간을 구분: step의 tick은 계속 증가하고 입력·탄 충전·일부 상태를 처리한 뒤 hitstop 분기에서 물리/후속 전투 갱신을 건너뛴다. 모든 timer를 멈추는 구현이 아니다. 싱글 게임 사례이며 멀티 안전성을 입증하지 않는다.
  • 유예의 게임별 의미: 바운코 COYOTE는 발판 점프가 아니라 그림자 도착 후 돌진 입력의 유예다. 150ms 동안 charge가 .94→.70으로 줄어든다. dash.inputBufferMs 입력 예약과도 구분한다.
  • 가져올 원리: 준비 위치와 발사 위치 일치, 한 성공 사건의 반동/외형/소리, 실제 명중만의 보상, 기술별 쉼의 대비. 이 사례의 ms·속도·거리·피해 예산은 게임별 config로 다시 조절한다.

  • 반복 전투의 피로와 motion sickness는 단일 효과 감상과 별개로 관찰한다. 390px·최대 개체 수·동시 다중 타격·저사양에서 비교한다.

7. 멀티·롤백 계약

공식 사실과 BLOOM 권장 설계를 구분한다
아래 공식 자료는 입력·결정론·상태 복원·표현 분리의 근거다. 특정 ms, freeze 범위, 유예/중첩 정책은 우리 게임이 선택하고 검증할 설계다. 멀티에서 hitstop이 불가능한 것은 아니다.

P2P에서는 공유 결정론 시뮬레이션이 같은 입력/규칙을 실행한다. 서버 권위 예시에서는 승인된 입력으로 권위 상태를 계산하고 클라이언트가 예측한다. 둘 다 “무엇이 게임 결과를 바꾸는가”가 상태 복원의 기준이다. 서버 예측 구조가 모두 서버 전체를 롤백한다는 뜻은 아니다. 서버의 과거 hitbox 조회도 세계 전체 재시뮬과 다르다.

7.1. 코요테·입력 버퍼·지연 보상은 별개다

코요테 타임 발판을 떠난 뒤 짧게 점프를 허용하는 유예. Celeste 개발자 설명의 이동 관용 사례다. 바운코의 도착 후 돌진 유예는 이 이름을 다른 행동에 적용한 게임별 규칙이다.

게임플레이 입력 버퍼 행동이 가능해지기 전에 들어온 입력을 제한 시간 보존해 가능 시 실행. 같은 개발자 글의 착지 직전 점프와 대응한다.

짧은 탭 캡처 latch tick 사이 press/release를 수집 시점까지 잃지 않게 하는 장치 경계다. 이후 몇 tick 동안 행동을 예약하는 게임플레이 버퍼와 다르다. Fusion 입력 수집/틱 실행.

네트워크 지연 보상 예를 들어 서버 권위 슈터가 플레이어가 봤던 과거 타깃의 hitbox를 조회하는 판정 정책. Fusion lag compensation. 코요테나 버퍼를 RTT만큼 늘리는 것과 다르다.

BLOOM 권장: 유예 판정은 벽시계/패킷 도착 시간이 아니라 승인한 입력 대상 tick에서 한다. 입력 소유 player/entity와 command sequence, 대상 tick, 명령 종류를 확인한다. 임의의 클라이언트 과거 timestamp를 그대로 신뢰하지 않는다. P2P의 공동 규칙·허용 입력 범위와 서버의 검증 정책은 구조에 맞게 명시한다.

  • lastGroundedTick, bufferExpiryTick, jumpConsumed, 이전 버튼 edge, 사용한 명령 sequence 등 결과에 영향을 주는 모든 상태를 save/load 및 rollback snapshot에 넣는다. 입력 로그만 되감고 timer를 남기지 않는다.
  • 접지→이탈→유예→만료와 점프 성공의 전이를 정한다. 정상 점프 직후 코요테 재점프가 되지 않도록 접지 갱신 순서와 소비 flag를 관리한다. 성공하면 해당 버퍼와 유예를 함께 소비하고, 새 착지에서만 재무장한다.
  • 버퍼의 성공·만료·새 입력 교체·취소·정지 중 보존 여부, 경계 비교의 포함/제외와 같은 tick 입력 우선순위를 결정한다. 만료 절대 tick을 쓰면 freeze 중에도 만료하므로 정지시키려면 별도 활성 tick 시계나 명시적 기한 조정이 필요하다.
  • 입력 지연·유예·버퍼·클라이언트 예측·lag compensation의 목적과 값을 별도로 조정한다. RTT가 큰 사람에게 자동으로 더 긴 게임 유예를 주지 않는다.

GGPO 개발 가이드는 결정론, 직렬화 가능한 완전 상태와 렌더 없이 한 프레임을 재실행할 수 있어야 함을 요구한다. 위 필드와 소비 규칙은 이를 이동/전투에 적용한 설계 예시이며 GGPO의 전용 coyote API가 아니다.

7.2. 규칙을 멈추는가, 표현을 유지하는가

종류무엇이 달라지는가복원·운영 계약
게임플레이 hitstop이동·공격시간·충돌/히트 판정 기회가 달라진다. entity별 또는 전체 전투 세계 범위.정지 대상/범위, 원인, 남은 tick, 중첩 정책을 canonical 상태에 저장. 모두 같은 tick에서 시작·해제·재시뮬.
표현 전용 hold외형 pose·국소 VFX만 유지하고 권위 시뮬레이션은 진행한다.렌더 시계와 자원 journal에서 관리. collider가 이미 움직이면 시각 오차·복귀 보정·조준 신뢰를 확인. 판정에 쓰는 뼈/pose를 멈추면 더 이상 표현 전용이 아니다.

Fusion Animation은 판정용 애니메이션과 표시를 구분할 근거이며, SnapNet Simulation vs. Presentation은 시뮬레이션과 연속 표현의 책임 분리를 설명한다. 아래 freeze 정책은 BLOOM의 적용 제안이다.

  • 시뮬레이션 tick은 계속 전진시키고 해당 entity/서브시스템의 업데이트를 gate한다. P2P/권위가 같은 freeze 상태를 적용한다. 전역 전투 정지는 다른 참가자의 전투까지 멈추게 하는 게임 규칙 선택이다.
  • 입력·네트워크 시간은 별도로 수집/송수신/정비하고 rollback 스케줄도 유지한다. hitstop 연출을 위해 global simloop/network를 timeScale=0 또는 loop stop으로 통째로 멈추지 않는다. 연결 정지·진짜 pause는 별도 계약이다.
  • 렌더 시간은 pose hold·쉐이크·오디오 수명에 사용한다. 권위 tick과 원격 보간 timeline을 구분하고 로컬 외형 보정이 명중 판정을 바꾸지 않게 한다.
  • 시계별 표를 먼저 작성: 움직임·attack active/recover·stun·coyote·buffer·cooldown·재장전·경기시간을 각각 freeze/진행 중 하나로 정한다. 바운코의 탄 충전 진행을 모든 게임에 강제하지 않는다.
  • 다중 hitstop은 max(남은 값, 새 값), 더하기, 우선순위 중 규칙 하나와 상한을 정한다. 상대와 공격자 중 한쪽만 멈추면 충돌·거리·콤보가 어떻게 바뀌는지 확인한다. 이미 처리한 명중이 정지 중 반복 판정되지 않게 한다.

7.3. 예측·확정·취소 · 중복도 유실도 막는다

SnapNet Events는 예측 이벤트의 재실행·취소와 외부 효과를 다루는 1차 자료다. BLOOM 권장: 공격자ID + 공격 instance + 피해자ID + 타격 index 같은 안정적인 논리 키로 결과 집합을 비교한다. 좌표 float·패킷 도착 시간·렌더 프레임·재실행 때 바뀌는 난수는 identity로 삼지 않는다. entity 재사용에는 generation/세션 수명도 포함한다.

  1. 정규/재시뮬 step은 순수한 사건 데이터를 만든다. 사운드·DOM·VFX를 매 step에서 무조건 직접 실행하지 않는다. resimulating이면 전부 버리기도 새로 유효해진 타격을 유실한다.
  2. 같은 사건이 다시 나오면 기존 자원을 reconcile하고 확정 시 재시작하지 않는다. 새 유효 사건은 생성, 사라진 예측 사건은 취소한다. 이미 끝난 자원도 허용 롤백 구간 동안 dedup 기록을 유지한다.
  3. 예측 VFX/표현 freeze는 취소 시 남은 hold를 해제하고 실제 표시로 보정한다. 게임플레이 freeze는 snapshot 복원과 재시뮬 결과에서 제거한다. 화면 보정만으로 규칙 상태를 고치지 않는다.
  4. 이미 들린 소리는 되돌릴 수 없다. one-shot은 확정 후 재생하거나, 낮은 지연이 꼭 필요하면 남은 부분 fade/끝까지 재생 정책을 명시한다. 취소 가능 자원이라는 이유로 이미 들린 순간까지 되돌린다고 쓰지 않는다.

원격 표현: SnapNet Interpolation vs. Prediction처럼 로컬 예측과 원격 표시 시간선이 다를 수 있다. 사건 tick을 원격 render timeline의 시각에 매핑한다. 패킷 도착 즉시 항상 전체 효과를 시작하면 몸체와 타격이 어긋난다. 늦은 사건은 남은 수명만 재생/짧은 대체/생략 중 정책을 정한다. 필수 피해·상태 결과는 효과 생략과 무관하게 반영한다.

7.4. 현재 GameKit 공식 API ↔ 실제 구현

조회 기준 c6ed368, 2026-10-15 UTC. 다음은 해당 README·CONTRACT와 구현을 함께 읽은 내용이다. Bounko는 자체 고정 SDK 핀을 쓰므로 최신 GameKit main과 같은 버전이라고 가정하지 않는다.

  • input README / actions.js: ActionState와 createDOMInput, 명시적 consume()으로 edge를 소비한다. input 모듈은 simulation tick·명령 큐·권위 상태·월드 좌표·게임플레이 유예를 소유하지 않는다.
  • rollback 계약 / 공식 API / core.js 구현: 게임 어댑터의 save/load/step이 완전 상태와 규칙을 소유한다. step({tick,inputs,resimulating,recovering,replaying}) 경계에서 게임이 사건을 만든다. 세션의 submitInput(input,{commands})는 명령별 불변 executeTick을 예약하며 그 호출 자체로 simulation을 진행하지 않는다. queueCommand도 같은 예약 경로다. ACK를 실행 확인으로 취급하지 않는다.
  • simloop README / loop.js: createLoop의 observeInput/pollInput/pulse/render는 장치 관측·정비·시뮬·표현 경계를 나눈다. hitstop 때문에 loop 자체를 중단하는 API 사용을 권하지 않는다.
  • presentation-events README / 실제 index.js: PresentationEventQueue.emit, beginRollback/endRollback, confirmThrough/update/finish/dispose가 있다. 실제 identity는 [tick,sequence,entityId,generation,kind]이다. 위 논리 공격 키를 이 필드들에 결정론적으로 매핑하는 것은 게임 책임이며 SDK identity를 다른 형태라고 설명하지 않는다.

journal 연결의 제약: 기본 confirmed는 확정 뒤 start, speculative는 reversible:true와 stop이 있는 adapter만 허용된다. rollback 이벤트에서 begin, reconciled에서 end, Math.min(session.confirmedTick,session.tick-1)가 0 이상일 때 confirmThrough한다. recovery 후보는 성공 전 외부 자원을 만들지 않는다. 세션/epoch 교체는 기존 자원을 정리하고 별도 수명으로 분리한다.

시각은 자동 매핑되지 않는다: journal의 tick은 순서이고 nowMs/durationMs는 표현 시간이다. 실제 구현은 start 시각부터 수명을 잰다. 원격 사건 tick→표시 시각 매핑과 늦은 효과의 나이 계산은 게임 adapter에서 처리한다. SDK가 자동으로 과거 효과를 seek한다고 쓰지 않는다.

위 모듈에 게임별 코요테/버퍼/hitstop 규칙을 제공하는 전용 API는 없다. setCoyoteTime()·setHitstop() 같은 가상의 GameKit API를 만들지 않는다. 게임이 상태와 freeze 정책을 구현하고 기존 입력·롤백·표현 경계를 연결한다. A051 표현 이벤트 중복 제거 / A063 시간선 재타기팅의 원리도 함께 읽는다.

8. 적용·검증 체크리스트

다음은 게임에 적용할 때의 권장 검증이다. 이번 문서 편집에서 실제 멀티/전투 검증을 모두 실행했다는 뜻은 아니다. 문서 자체의 실행·링크 검사 결과는 PR에 기록한다.

  • 행동 하나의 준비→발사→명중/실패→회복을 무음·효과 축소에서도 설명할 수 있다.
  • 판정 접점/방향·실제 피해·hitflash·충격음이 같은 사건에 연결된다. 무적/막힘/빗나감은 성공과 구분한다.
  • 각 효과를 하나씩 끄고 비교한다. 국소 효과만으로 충분한지 확인하고 밀집 전투에서 플레이어·아군·다음 위협을 추적한다.
  • 게임별 config에 강도·수명·중첩 상한을 모으고 동일 상태를 렌더·물리·UI가 중복 소유하지 않는다. 리셋/사망/취소 뒤 잔여 효과·반동·오디오를 정리한다.
  • 유예·버퍼 경계 ±1 tick, 정상 점프 직후 재점프 차단, 성공 시 한 번 소비, 정지 중 입력 예약·만료를 확인한다.
  • 입력 지연·jitter·손실·중복을 주고 같은 대상 tick/sequence가 한 번 실행되는지 확인한다. packet ACK와 실제 실행 확인을 구분한다.
  • 정지 직전/도중 snapshot을 복원해 같은 입력 뒤 같은 위치·피해·timer·타격 수가 나오는지 비교한다.
  • 예측 타격을 rollback으로 취소하고 남은 freeze/VFX 정리, 중복 음향 없음, 새로 유효해진 사건의 유실 없음, 확정 재시작 없음을 확인한다.
  • 다중 타격/동시 freeze, 상대만 정지/양쪽 정지, 관전자·원격 보간 시점, 늦은 효과 정책을 확인한다.
  • 20/30/60TPS와 다른 렌더 FPS에서 실제 정지 시간·유예·버퍼·타격 수를 비교한다. 공격 시간 배율을 바꿔 피해 펄스가 늘지 않는지 확인한다.
  • 390px/PC·장시간 반복·효과 축소·무음, 카메라 흔들림 중 조준 역변환과 HUD 고정을 확인한다.
