1.개요 · 변경 비용과 체감 효과

이 문서는 최근 BLOOM 게임에서 반복 사용하거나 사용자가 지적해 개선한 UI/UX 공통 기준의 단일 HTML 원본이다. 지금 내려야 할 결정과 실제 행동·결과를 읽게 만드는 것을 장식보다 먼저 다룬다.

표시의 구분
  • 확정 원칙: 사용자 요청으로 확정한 공통 방향. 각 우선순위 절의 기본 규칙이다.
  • 게임 사례: 특정 프로젝트의 구현·기획 맥락. 수치·확률·슬롯 수·시간을 다른 게임의 기본값으로 옮기지 않는다.
  • 새 권장안 / 설명 예시: 이 원칙을 적용하기 위한 문서의 제안과 비교 예시. 사용자 확정 디자인이나 구현 완료 보고와 구별한다.

P1 → P10은 후변경 비용과 적용 시 체감 효과를 함께 고려한 내림차순 권장 순서다. 메뉴·상태·좌표처럼 여러 화면이 의존하는 계약을 먼저 정하고, 자주 만나는 조작과 선택을 개선한 뒤 연출을 연결한다. 수치 점수는 사용하지 않는다. 해당 기능이 없는 게임은 건너뛰며, 현재 결함이 플레이를 막으면 그 수정을 먼저 한다.

  1. P1 URL과 화면 상태 — 공유·새로고침·복귀 계약을 뒤늦게 바꾸면 모든 메뉴가 영향을 받는다.
  2. P2 공통 상태와 생명주기 — 저장·구매·입력·팝업에 걸친 오류를 원천에서 줄인다.
  3. P3 좌표와 렌더의 일치 — 모든 표식과 피드백이 기대는 기반이다.
  4. P4 모바일·입력·메인 동선 — 첫 플레이와 매번 하는 선택의 체감 효과가 크다.
  5. P5 문구·숫자·가독성 — 문구와 계산이 흩어진 뒤 고치면 화면·데이터를 함께 바꿔야 한다.
  6. P6 테크트리와 조건 조회 — 의존 관계와 카드 배치를 먼저 정해야 성장 선택을 이해한다.
  7. P7 시각 위계와 군중전 — 플레이어·위협을 놓치는 문제를 즉시 줄인다.
  8. P8 조작 단계와 피드백 — 입력과 실제 판정의 연결이 타격감과 신뢰를 만든다.
  9. P9 보상·해금·성장 — 얻은 변화와 보상 확정을 읽게 만든다.
  10. P10 프리뷰·소개 — 앞의 공통 실행을 재사용해 선택과 직접 플레이를 돕는다.
그리기 전에 답할 네 가지
  1. 누가 무엇을 판단하는 화면인가?
  2. 지금 놓치면 손해인 정보는 무엇인가?
  3. 어떤 입력을 할 수 있고 결과는 어디에서 확인하는가?
  4. 개체와 효과가 겹쳐도 그 답이 남는가?

한산한 정지 화면뿐 아니라 혼잡 전투, 작은 화면, 효과 축소 상태와 실제 입력에서도 검토한다. 특정 미술 양식·불투명도·흔들림 강도를 공통 고정값으로 강제하지 않는다.

2.P1 · URL과 화면 상태 동기화

우선순위 P1 · 이유 공유·새로고침·브라우저 이력은 여러 메뉴의 공통 계약이다. 진입 처리만 만들면 복귀·F5 오류가 남는다.

언제 쓰는가 위키·도움말·소개 등 직접 공유하거나 새로고침할 가치가 있는 공개 화면.

확정 원칙
공개 메뉴는 직접 URL로 진입할 수 있어야 한다. 메뉴 열기·닫기·메인 복귀가 실제 주소를 갱신하고, 뒤로·앞으로·F5가 같은 화면을 복원한다. 최초 파라미터 읽기만으로 완료하지 않는다.
  • 화면을 전환하는 한 경로에서 화면 상태와 URL을 함께 갱신한다. 이력 복원은 다시 이력을 추가하지 않는다.
  • 메인 복귀 시 소개·위키를 가리키는 주소 상태도 해제한다. 공유 주소는 사용자가 보고 있는 공개 화면을 설명해야 한다.
  • 공개 라우트와 프리뷰 내부의 격리 iframe 주소를 구분한다. 내부 실행 페이지를 공개 메뉴 경로로 취급하지 않는다.
  • URL은 화면·조회 상태를 나타낸다. 구매·합성·소모 같은 상태 변경 명령을 URL 진입이나 이력 복원으로 실행하지 않는다.

새 권장안 공개 메뉴별 URL·진입·복귀 규칙을 작은 라우트 표로 합의한다. 구체 path/query 형식과 이력 추가·교체 선택은 프로젝트의 기존 주소 계약을 따른다.

나쁜 예 → 좋은 예 설명 예시
소개 링크로 들어와 메인으로 돌아갔는데 주소에 showcase=1이 남아 F5 후 소개로 돌아간다 → 메인 복귀와 주소 정리를 함께 수행하고 F5·뒤로·앞으로로 다시 확인한다.
완료 체크
직접 링크 → 메뉴 → 메인 → F5, 메뉴 열기 → 뒤로 → 앞으로, 닫기 → 재열기가 화면과 주소에서 일치한다. 링크 진입만으로 구매·합성이 발생하지 않는다.

게임 사례 · 바운코의 URL 메뉴 개선은 별도 작업이 진행 중이다. 이 절은 완료 기준이며 해당 작업의 구현·검증 완료를 뜻하지 않는다.

3.P2 · 공통 상태와 생명주기

우선순위 P2 · 이유 여러 UI가 상태를 복제하면 구매·저장·취소 경계마다 어긋난다. 팝업 자원 누수는 재열 때 누적된다.

언제 쓰는가 성장·장착·상점·프리뷰·설정 등 실제 상태를 조회하거나 바꾸는 화면.

확정 원칙
실제 상태의 소유자는 하나이며 UI는 같은 상태와 확정 사건을 읽는다. 선택·조건 조회와 구매·소모를 분리한다. 잠긴 항목도 조건과 예상 효과를 조회할 수 있다.
  • 카드 선택·상세 열기·프리뷰는 구매가 아니다. 확정 동작에서만 비용과 조건을 검사하고 상태를 변경한다.
  • 닫기·취소·뒤로·재열기에서 원래 선택, 스크롤, 실행 버튼 포커스를 복원한다. 제거된 항목이면 의미 있는 인접 위치로 돌아간다.
  • 팝업 동안 게임 입력을 격리한다. 입력란·단축키·터치가 뒤의 전투나 구매로 새지 않게 하고 눌림 상태도 정리한다.
  • 열 때 만든 루프·오디오·타이머·리스너는 닫기·취소·화면 전환에서 정리한다. 재열 때 중복 실행하지 않는다.
  • 프리뷰나 소개의 별도 실행 인스턴스는 분리된 수명을 가진다. 본게임 저장과 진행 상태를 공유해서 수정하지 않는다.

상태 소유권·읽기/쓰기·사건 소유권의 기술 계약은 개발 규칙에서 관리한다.

나쁜 예 → 좋은 예 설명 예시
카드 탭이 즉시 포인트를 쓰고, 닫았다 열 때 재생 루프가 두 개가 된다 → 탭은 조회하고 별도 구매 버튼이 확정한다. 닫기에서 실행을 정리한 뒤 같은 선택 위치로 재열한다.
완료 체크
잠긴 항목 조회·취소가 자원을 바꾸지 않는다. 닫기/뒤로/재열기 후 포커스·스크롤·입력이 맞고 루프·오디오·타이머가 중복되지 않는다.

4.P3 · 좌표·시간·렌더의 일치

우선순위 P3 · 이유 좌표와 시간 계약이 어긋나면 모든 숫자·그림자·표식을 각각 보정하게 된다. 뒤늦은 수정 비용이 크다.

언제 쓰는가 높이가 있는 월드, 이동·회전·카메라, 피격 숫자와 지면 표식이 있는 게임.

확정 원칙
월드 x/y/z와 UI 앵커·그림자·피격 숫자는 같은 투영을 따른다. 언덕 높이를 반영하고 TPS와 렌더를 분리해 보간한다. 시간 데이터는 ms로 정의한다.
  • 숫자와 상태 표시는 실제 화면에 보이는 대상·명중 위치에 붙는다. 이동·언덕·카메라 변화에서도 따로 미끄러지지 않는다.
  • 지면 그림자는 지면에, 몸체·피격 숫자는 해당 높이에 붙는 의미를 유지한다. 화면 좌표를 임의 복제하지 않는다.
  • 연타의 숫자를 하나로 합쳐 타격 리듬을 없애지 않는다. 장식 밀도를 먼저 낮추고 각 확정 타격의 시점을 유지한다.
  • 렌더 프레임 수가 전투 시간·공격 횟수·보상 확정을 바꾸지 않는다. 보간은 표시를 부드럽게 하며 실제 판정을 새로 만들지 않는다.

보간·시뮬레이션/렌더 분리는 개발 규칙과 GameKit 모듈, 높이·통행 의미는 지형 레퍼런스로 연결한다. 여기서는 구현 공식을 중복 설명하지 않는다.

나쁜 예 → 좋은 예 설명 예시
언덕 위 적의 피해 숫자는 평지 좌표에 뜨고 연타는 합계 한 번으로만 보인다 → 같은 높이 투영으로 시각 명중점에 숫자를 띄우고 연타 시점을 각각 전달한다.
완료 체크
평지·언덕·이동·카메라 변화에서 몸체/앵커/숫자/그림자가 같은 좌표 계약을 따른다. 서로 다른 렌더 속도에서도 행동 횟수와 시간이 같다.

5.P4 · 모바일·입력·메인 동선

우선순위 P4 · 이유 첫 화면과 반복 조작은 모든 플레이에 영향을 준다. 좁은 화면의 동선을 먼저 정하면 나중에 UI를 대폭 줄일 필요가 적다.

언제 쓰는가 메인, 전투 HUD, 성장·보상 선택과 터치 조작.

작은 화면에서 핵심 선택지, 비교에 필요한 차이, 비용과 보상, 선택 결과를 확인하기 위해 위아래를 불필요하게 왕복하지 않게 구성한다. 화면 높이에 맞춘다는 이유로 글자와 터치 영역을 과도하게 줄이지 않는다.

  • 선택 카드에는 결정에 필요한 요약과 현재 선택 상태를 가까이 둔다.
  • 보상 수령 버튼 주변에서 무엇을 받는지와 수령 결과를 확인할 수 있게 한다.
  • 긴 설명·도감·세부 능력치는 펼침 패널 또는 별도 상세 보기로 제공할 수 있다.
  • 상세를 닫으면 원래 선택과 위치를 유지한다. 뒤로 가기·취소·재선택도 확인한다.
  • 실제 작은 뷰포트, 화면 회전, 긴 번역 문구, 큰 글자, 안전 영역과 손가락 가림을 점검한다.
나쁜 예 → 좋은 예
강화 카드를 읽고 화면 맨 아래 비용을 확인한 뒤 맨 위로 돌아와 선택한다 → 카드 근처에 핵심 효과와 비용을 두고 선택 요약·확정 동작을 같은 흐름에서 확인한다. 긴 계산 설명은 상세 패널로 분리한다.

스크롤 전면 금지 규칙이 아니다. 목록이나 상세 문서의 자연스러운 스크롤은 허용한다. 문제는 같은 결정을 내리려고 이미 본 정보를 여러 번 찾아 왕복하거나, 고정 패널이 실제 내용을 가리는 구조다. 고정 버튼을 쓰면 마지막 항목과 포커스가 가려지지 않는지도 확인한다.

확정 원칙 · 시작과 플레이를 먼저
메인 화면에서는 게임 시작을 우선하고 세부 정보는 점진적으로 공개한다. 화면을 가리는 상시 UI를 최소화한다. 버전은 메인 구석에서 바로 확인할 수 있게 한다.
  • hover에 의존한 조건·툴팁은 탭·키보드로도 조회한다. PC와 모바일은 같은 의미·확정/취소 계약을 갖는다.
  • 손가락 가림과 터치 위치를 고려하고 입력과 표시가 겹치지 않게 한다. 작은 화면에 맞추려 글자·터치 영역부터 줄이지 않는다.
  • 사망은 화면 전체 차단 대신 짧은 비차단 안내와 자동 부활로 흐름을 이어 간다. 부활 대기와 다음 상태는 읽을 수 있어야 한다.

게임 사례 바운코의 자동 부활 3초는 그 게임의 사례다. 공통 부활 시간으로 고정하지 않는다. 확인 대화가 필요한 다른 상태 변경과 사망 안내를 혼동하지 않는다.

나쁜 예 → 좋은 예 설명 예시
메인을 도감과 설명으로 덮고 사망마다 전체 화면 확인을 요구한다 → 시작을 눈에 먼저 두고 자세한 정보는 요청 시 펼친다. 사망은 짧게 알리고 자동 부활한다.
완료 체크
390px 실제 크기에서 시작·핵심 입력·선택·확정을 읽고 누른다. hover 없이 조회한다. 상세 복귀·긴 문구·큰 글자·회전·안전 영역에서 내용이 가려지지 않는다.

6.P5 · i18n·숫자·가독성

우선순위 P5 · 이유 문구와 내부 계산이 화면마다 섞이면 언어·밸런스 변경이 여러 화면의 동시 수정으로 번진다.

언제 쓰는가 다국어 UI, 가격·확률·효과·다음 성장 표시.

확정 원칙
표시 문구를 실행 코드와 분리하고 공개 i18n 라이브러리를 활용한다. 사용자가 읽는 값은 실제 최종 효과다. 의미 없는 내부 배율을 “효과 2배”처럼 노출하지 않는다.
  • 확률·비용·현재 효과·다음 효과를 같은 정의에서 표시해 투자 결과를 예측할 수 있게 한다. 단위·반올림·조건은 STAT 계약을 따른다.
  • 언어 전환 시 선택·진행 상태·스크롤을 유지한다. 화면을 초기화하거나 저장 언어와 화면 언어가 따로 남지 않게 한다.
  • 번역이 길어져도 핵심 버튼·숫자·조건이 잘리지 않게 한다. 대비, 글자 크기, 터치 영역을 실제 화면에서 확인한다.
  • 피해·회복·돈 숫자는 색뿐 아니라 기호·아이콘·단위·위치 등으로 역할을 구별한다.

게임 사례 바운코 v0.14.6은 i18next 기반 한국어·영어 문구 분리와 저장 언어 적용을 설명한다. 공통 원칙은 특정 라이브러리·언어 수의 고정이 아니다.

나쁜 예 → 좋은 예 설명 예시
내부 계산 보정값 2를 “효과 2배”로 표시하고 언어 전환이 트리를 처음 위치로 돌린다 → 실제 결과와 다음 효과를 단위와 함께 보여 주고 같은 카드·스크롤에서 언어만 바꾼다.
완료 체크
표시값과 실제 효과가 맞는다. 확률·가격·다음 효과를 예측할 수 있다. 긴 번역 전환에도 상태·스크롤·버튼 가독성이 유지된다.

7.P6 · 테크트리·조건 조회·선택 경로

우선순위 P6 · 이유 선행 조건과 그래프 배치를 잘못 읽으면 성장 선택 자체가 어려워진다. 노드가 늘어난 뒤 연결 구조를 바꾸는 비용이 크다.

언제 쓰는가 복수 선행 조건, 해금 경로, 업그레이드·연구 그래프.

확정 원칙
A+B 모두 필요라는 의미를 아이콘 조합·조건 n/N·합류점으로 명시한다. 충족한 개별 조건선과 선택 경로를 강조하고, 조건 조회와 구매는 분리한다. 잠긴 노드의 기존 프리뷰도 유지한다.
  • 선을 따라가야만 AND 조건을 추측하게 하지 않는다. 카드 상세에서도 각 선행 조건과 충족 여부를 읽을 수 있게 한다.
  • 연결선은 카드 관통과 선 중첩을 피한다. 불가피한 교차는 합류점과 다른 모양으로 표시한다.
  • 선택 노드·연결 경로·충족 상태가 구별되어야 한다. 색 이외에 선 패턴·표식·라벨을 함께 사용한다.
  • 조회 후 돌아오면 기존 트리 위치와 선택을 유지한다. 구매 가능한 버튼과 미충족 이유는 구분하고 비용은 확정 동작 가까이에 둔다.
참고 사례 · 무엇을 가져올 것인가
  • Nova Drift 공식 2018 Year in Review는 복수 구매 조건을 가진 Super Mod와 트리 개편 사례다. A+B 조건 전달의 참고이며 최신 UI 전체를 재현하라는 뜻은 아니다.
  • Factorio 공식 FFF-238 (2018-04-13)은 노드 가까이에 상세·상호작용을 묶고 상태를 일치시키는 당시 설계다. 2018년 개발 중 설계이며 최신 UI라고 부르지 않는다.
  • Vampire Survivors의 Grim Grimoire는 발견한 진화 레시피 조회 사례다. 연결 테크트리의 예로 분류하지 않는다.

새 권장안 직접 연결된 조건은 카드 가까이에 묶고, 선택 경로만 강조한다. 레이아웃·선 모양은 실제 노드 수와 작은 화면으로 결정한다.

나쁜 예 → 좋은 예 설명 예시
A와 B가 모두 필요한데 선 두 개만 그려 OR처럼 읽히고, 선이 중간 카드를 관통한다 → A+B 아이콘과 조건 1/2, 개별 충족선·합류점을 보여 주고 교차와 합류를 구별한다.
완료 체크
A만/B만/둘 다 충족한 대표 상태에서 구매 가능 의미가 맞는다. 잠긴 카드 조회·프리뷰가 가능하고 선택 경로·선 교차·복귀 위치를 실제 화면에서 읽는다.

8.P7 · 정보 위계와 시각 예산

우선순위 P7 · 이유 전투 대상을 놓치는 문제는 즉시 체감된다. 공통 실루엣 문법을 먼저 정하면 장식마다 보정을 반복하지 않는다.

언제 쓰는가 배경·대상·위협·행동 피드백이 함께 있는 화면.

확정 원칙
배경·장식 < 전투 대상 < 핵심 위협·행동 피드백 순으로 읽힌다. 작은/큰 도형의 실루엣과 역할을 일치시키고 색만으로 의미를 전달하지 않는다.

플레이어·위협·공격 표시·입력 결과가 배경 장식에 묻히지 않게 한다. 이들 사이의 세부 우선순위는 현재 결정에 따라 달라진다. 즉시 회피가 필요하면 위협이, 보상을 고르는 화면이면 선택지와 확정 결과가 주의를 받아야 한다.

표현 자원중요 정보에 할당장식에서 절제할 것
대비·채도배경과 분리되는 실루엣, 위험 경계와 조작 상태모든 타일·풀·먼지에 동일하게 강한 대비와 채도
불투명도판정 경계와 읽어야 할 대상이 유지되는 겹침 설계넓은 반투명 효과가 누적되어 화면 전체를 덮는 현상
크기·외곽선추적해야 할 주체와 작은 핵심 표식의 분리소품과 비전투 효과까지 같은 굵은 외곽선 사용
움직임·점멸새 위협, 상태 전환, 입력 확인에 필요한 제한된 변화상시 흔들리는 배경, 모든 보상과 피해에 동시 점멸

시각 예산은 상대적인 주목도 배분을 뜻한다. 모든 요소를 더 크고 밝게 만드는 방식으로 해결하지 않는다. 우선순위가 낮은 요소의 강도·밀도·지속시간을 줄인 뒤 핵심 정보를 보강한다. 공통 불투명도 수치나 외곽선 두께를 강제하지 않는다. 카메라, 재질, 배경, 효과 중첩과 기기에서 읽히는지를 근거로 조정한다.

나쁜 예 → 좋은 예
화려한 풀과 탄환이 같은 채도·크기로 움직여 플레이어를 잃는다 → 풀의 변화량과 대비를 낮추고 플레이어 실루엣 및 탄환 진행 방향을 분리한다. 배경 전체를 무조건 흐리게 하는 대신 필요한 정보의 경쟁 요소를 찾는다.
완료 체크
작은 화면·회색조·효과 축소에서도 핵심 대상과 위협을 설명할 수 있다. 실루엣·외곽선·움직임이 역할과 일치하고 장식 강도가 이를 넘지 않는다.

8.1.P7 · 혼잡 전투와 아군 구별

우선순위 P7의 적용 · 이유 한산한 화면의 좋은 대비도 군중전에서 무너질 수 있다. 위계와 같은 묶음으로 검토한다.

언제 쓰는가 다수 적·아군·동시 공격·최대 성장 장면.

적 한 마리와 효과 한 개만으로 판단하지 않는다. 실제로 가능한 밀집도, 여러 공격의 동시 발생, 좁은 통로와 지형 경계, 카메라 이동을 포함한 장면에서 검토한다.

  • 플레이어 위치와 진행 방향을 지속해서 추적할 수 있는가?
  • 해로운 범위·투사체와 이미 끝난 잔상을 구분할 수 있는가?
  • 지형의 통과 가능 경계와 배경 장식을 혼동하지 않는가?
  • 데미지 숫자·획득 텍스트가 다음 회피 정보나 목표를 가리지 않는가?

겹침이 심하면 장식 파티클 수, 잔상 수명, 비핵심 텍스트 중복, 비핵심 효과 면적부터 조정한다. 중요 경고와 실제 공격의 정보를 효과 품질 옵션으로 함께 지우지 않는다. 표시를 단순화하더라도 방향·범위·발생 시점 등 플레이 판단에 필요한 의미는 유지한다.

나쁜 예 → 좋은 예
폭발을 크게 키워 명중감을 만들었지만 바닥의 다음 공격 경고가 사라진다 → 명중 부위의 짧은 반응과 명확한 타격 실루엣으로 결과를 전달하고, 다음 위협 경계를 읽을 공간을 남긴다.

지형의 형태와 통행 정보는 지형 생성 레퍼런스와 함께 확인한다. 화면 표시와 실제 충돌·이동 판정이 어긋나면 시각 보정만으로 덮지 않는다.

확정 원칙
군중전에서 모든 적의 등급 텍스트를 반복하지 않는다. 등급색 외곽선과 크기·형태·표식을 조합하고 아군을 구별한다. 피해 연타 숫자를 합쳐 타격 리듬을 없애는 방식으로 혼잡을 해결하지 않는다.
나쁜 예 → 좋은 예 설명 예시
적마다 긴 등급명이 겹치고 아군도 같은 실루엣이라 공격 대상을 잃는다 → 외곽선·크기와 보조 표식으로 등급을 읽게 하고 아군의 역할 표식을 구분한다. 상세 등급명은 조회에서 제공한다.
완료 체크
실제 가능한 밀집도에서 플레이어·아군·위협·공격 경계가 남는다. 다음 회피 정보가 숫자·잔상에 가려지지 않고 중요한 타격 시점이 사라지지 않는다.

9.P8 · 예고·차징·발사·명중·회복

우선순위 P8 · 이유 조작 단계와 실제 사건이 이어지면 입력 신뢰와 타격감이 함께 좋아진다. 앞의 상태·좌표 계약을 재사용한다.

언제 쓰는가 공격·차징·회피·스킬·탄약·쿨다운 피드백.

예고·입력→준비·차징→발사→명중·실패→회수·회복·대기

사용자가 “눌렸나?”, “아직 준비 중인가?”, “실제로 나갔나?”, “맞았나?”를 각각 판단할 수 있어야 한다. 차지가 없는 행동에 억지로 차지 단계를 추가하지 않고, 해당 행동에 존재하는 단계만 표현한다.

단계확인할 상태실수하기 쉬운 표현
입력수신·허용·거부, 선택 대상 또는 방향쿨다운으로 거부된 입력에도 성공 연출 표시
차지진행·최대치·취소·현재 발사 가능 여부실제 준비와 무관한 타이머로 게이지 완료
발사실제 실행 시점, 출발점과 공격 방향버튼을 누른 순간 명중처럼 큰 폭발 표시
명중실제 대상·판정 결과, 빗나감·막힘과의 차이판정 전 데미지 숫자 표시, 모든 충돌에 같은 성공 효과

피드백은 관련 상태 또는 확정된 사건에서 나온다. 네트워크 등으로 예측 표시가 있다면 최종 판정과의 경계를 정하고 취소·정정 흐름도 확인한다. 소리와 진동은 보완 수단으로 사용하며 꺼진 상태에서도 핵심 결과를 읽을 수 있게 한다.

강도는 의미에 맞게
모든 사건에 화면 흔들림을 붙이지 않는다. 필요한 사건만 강도를 구분하고 연속 발생 시 누적을 제한한다. 흔들림·점멸·잔상을 줄여도 필수 정보가 남도록 만든다. 타격감은 효과 개수가 아니라 시점·위치·반응의 일치로 검토한다.
확정 원칙 · 눈과 소리의 연속성
예고부터 다음 행동 가능 상태까지 실제 단계에 맞춰 전달한다. 궤도에서 준비하는 탄이 방향 정렬한 뒤 그 탄 자체가 날아가는 연속성을 유지한다. 반동·쉐이크는 공통 로직에서 강도와 종료를 관리한다.

소리는 각 단계의 보완 수단이며 소리가 꺼져도 의미가 남아야 한다. 회수·회복·장전·대기는 실제 완료 시점과 맞춰 표시한다.

적용 상황 시전 중 타겟이 사라져도 확정 위치·방향 기반으로 진행하는 공격은 그 전투 계약을 유지한다. 추적·취소형 공격은 자체 계약을 따른다. 모든 공격에 같은 지속 정책을 강제하지 않는다.

나쁜 예 → 좋은 예 설명 예시
준비 탄을 지운 뒤 새 탄을 순간 생성하고, 타겟 소실로 연출만 중단해 입력이 잠긴다 → 정렬한 실제 탄의 이동을 이어 보여 주고, 확정 공격의 종료·복귀에서 공통 제어와 반동을 정리한다.
완료 체크
예고/차징/발사/명중/회복이 실제 사건과 맞는다. 거부·취소·타겟 소실에서도 성공 연출이나 입력 잠금이 남지 않는다. 소리·효과 축소에서도 다음 행동 상태를 읽는다.

9.1.P8 · 이동·조준·자동 회피 표식

우선순위 P8의 적용 · 이유 같은 위치 표식의 서로 다른 의미를 분리해 행동 피드백을 완성한다.

언제 쓰는가 수동 목적지·공격 조준·시스템 회피가 함께 있는 게임.

비슷한 위치 표식이라도 의미와 수명은 다르다. 색만 다르게 하여 세 상태를 구분하지 않는다. 형태·선 패턴·방향·라벨·동작을 조합하고, 게임 안에서 일관된 문법을 사용한다. 아래 모양은 적용 예시이며 공통 고정 디자인이 아니다.

의미전달할 정보표현 예종료·변경 조건
수동 목적지사용자가 직접 지정한 이동 의도바닥 핀 또는 도착 고리 + 이동 경로도착·취소·새 목적지 지정 시 갱신
조준공격할 방향·대상·유효 범위십자선 또는 방향 부채꼴 + 사거리 경계조준 변경·공격 불가·해제에 맞춰 갱신
자동 회피시스템이 위협에 반응해 만든 임시 이동짧은 점선 곡선과 회피 화살표 + 필요 시 자동 표시회피 종료 시 사라지고 수동 의도 복귀 여부를 표시
나쁜 예 → 좋은 예
같은 원을 파랑·초록·빨강으로 바꾸어 목적지·조준·회피를 표시한다 → 목적지는 도착 핀, 조준은 방향선, 회피는 임시 화살표로 구분한다. 색을 빼거나 효과를 축소해도 역할을 설명할 수 있게 한다.

자동 회피 중 수동 목적지가 유지되는지 취소되는지는 실제 조작 계약을 따른다. UI가 별도의 목적지를 만들어 진짜 상태처럼 표시하지 않는다. 불가능한 위치를 입력했다면 성공 표식 대신 거부 이유 또는 가능한 대안을 전달한다.

완료 체크
색을 제거해도 이동 의도·공격 범위·임시 회피를 구별한다. 표식의 생성·종료가 실제 입력과 행동 수명에 맞고 불가능한 위치를 성공처럼 표시하지 않는다.

10.P9 · 보상·해금·성장의 실제 변화

우선순위 P9 · 이유 보상과 성장의 확정·체감이 어긋나면 선택의 의미를 잃는다. 확정 사건에 연결해 여러 화면에서 재사용한다.

언제 쓰는가 드롭·자석 회수·합성·해금·장착·능력 강화.

강화 전후를 눈으로 느낄 수 있게 하되 발사 개수·공격 범위·형태가 실제 게임 메커닉과 일치해야 한다. 보여 주는 수치와 판정은 스탯 규칙의 같은 정의를 읽는다. 시각 효과만을 위해 별도의 공격 개수나 사거리를 만들지 않는다.

성장 내용나쁜 예좋은 예
발사 개수 증가실제는 한 발인데 장식 탄환을 여러 발처럼 표시실제 발사된 각 탄환과 방향을 표시하고 잔상은 탄환과 구분
공격 범위 증가이펙트만 넓어지고 피해 범위는 그대로판정 범위와 대응하는 경계를 늘림. 장식 후광은 판정선과 구분
형태·패턴 변경직선 공격을 부채꼴처럼 보여 안전 구역을 오판실제 방향·분산·타격 구역의 변화를 새 실루엣으로 표현
피해량 증가피해만 늘었는데 폭발 반경도 크게 표시결과 수치나 국소 타격 반응으로 강화를 전달하고 범위는 유지
재사용 대기시간 감소버튼 게이지만 빨라지고 실제 발사는 이전 주기실제 준비 상태와 발사 주기에 맞춘 게이지·상태 전환

개수·범위가 크게 늘어 혼잡해지면 장식 밀도와 비핵심 반복 텍스트를 먼저 줄인다. 연타 피해 숫자를 합쳐 타격감을 없애지 않는다. 개별 공격을 묶어 그려야 한다면 실제 개수·위험 범위를 오해시키지 않는 표시 계약을 먼저 정한다. 메커닉을 바꾸지 않고 표현 문제를 다루되, 단순화가 정확성을 무너뜨리면 설계를 다시 검토한다.

드롭→자석 흡인→도착→보상 확정
확정 원칙
드롭·흡인·도착·보상 확정이 일치한다. 합성 성공·실패는 실제 결과 사건과 VFX로 전달한다. 얻었는데 아무 효과가 없는 해금을 만들지 않는다.
  • 흡인 시작만으로 잔액을 먼저 올리지 않는다. 도착과 지급 규칙이 같고 중복 지급하지 않는다.
  • 미발견 펫 종류를 처음부터 전부 노출하지 않아 발견 기대감을 보존한다. 이미 발견한 항목의 조건 조회는 유지한다.
  • 장착은 카드 탭 → 빈 슬롯으로, 장착 카드 탭 → 해제로 이어진다. 선택·장착·구매·합성의 의미를 혼동시키지 않는다.
  • 합성 전 비용·확률·예상 결과를 읽고, 성공·실패를 색 이외의 문구/모양으로도 확인한다. 해금 후 실제 사용·장착·효과 진입이 가능해야 한다.

게임별 config 구체 확률·성장 수치·흡인 거리·시간·슬롯 수는 게임별 설정이다. 이 문서의 흐름을 적용해도 모든 게임에 같은 숫자를 넣지 않는다.

나쁜 예 → 좋은 예 설명 예시
흡인 시작과 동시에 돈을 주고 도착 때 다시 지급하거나, 해금 후 사용할 곳이 없다 → 도착 사건으로 한 번 확정하고 잔액·획득 피드백을 일치시킨다. 해금 후 사용·장착 경로와 변화를 바로 확인한다.
완료 체크
드롭/흡인/도착/지급이 같은 사건을 따른다. 피해·회복·돈을 구별한다. 합성 성공/실패·해금·장착/해제가 실제 상태와 VFX에서 일치한다.

11.P10 · 프리뷰·소개·직접 플레이

우선순위 P10 · 이유 실제 공통 실행을 재사용하면 시연과 본게임의 차이를 줄인다. 앞의 상태·수명·피드백 기반이 있어야 안전하게 만들 수 있다.

언제 쓰는가 미해금 기술 시연, 게임 소개, 성장 비교와 선택 도움.

확정 원칙
실제 공통 시뮬레이션·렌더를 재사용하고 고정 seed·시작 상태로 반복 가능한 격리 시연을 만든다. 저장은 바꾸지 않으며 프리뷰는 자동 재생을 기본으로 한다.
  • 장식 영상만으로 실제 공격 범위·행동을 대신 설명하지 않는다. 본게임 실행과 같은 정의를 읽는 별도 인스턴스에서 시연한다.
  • 다시 보기·반복은 같은 시작 상태로 돌아간다. 닫기·취소·뒤로에서 실행·오디오를 정리하고 원래 조회 위치를 복원한다.
  • 소개는 여러 핵심 플레이를 보여 주고 직접 플레이 진입을 제공한다. 효과·카메라·문구는 데이터 시간표에서 관리한다.
  • 브라우저 자동 오디오 제한을 고려한다. 자동 시연은 무음으로도 이해되며 소리 켜기는 사용자의 선택이다.

게임 사례 바운코의 공개 소개는 28초 실시간 소개 사례다. 모든 게임의 소개 시간을 28초로 고정하지 않는다. v0.14.6 README는 격리 프리뷰의 실제 공통 실행·저장 차단·닫기 후 복귀를 설명한다. 최신 URL 메뉴 구현 완료 여부는 이 문서에서 단정하지 않는다.

나쁜 예 → 좋은 예 설명 예시
별도 연출용 공격을 만들어 본게임과 범위가 다르고 다시 보기가 저장 포인트를 바꾼다 → 같은 시뮬/렌더를 격리 인스턴스로 실행해 같은 seed로 반복하고 저장 불변을 확인한다.
완료 체크
자동 재생·다시 보기·반복이 같은 장면을 만든다. 전후 저장/본게임 상태가 같다. 닫기·재열기·소리 선택·직접 플레이 진입이 작동한다.

12.Reference-Driven · 구현과 실제 검증

확정 원칙
Reference-Driven으로 기존 시각·파티클 레퍼런스를 먼저 제안·재사용한다. 같은 렌더 primitive의 시안을 만든 뒤 실제 게임 화면과 핵심 입력 흐름으로 확인한다.
  1. 정보와 계약: 사용자의 판단·핵심 입력·결과·URL·실제 상태 소유자를 정한다.
  2. 기존 레퍼런스 제안: 파티클, UI·HUD, 실루엣·스타일, 전투 동작에서 맞는 표현을 먼저 찾는다.
  3. 같은 primitive 시안: 실제 렌더 경로로 형태·명암·역할부터 비교하고 색·재질·효과를 더한다.
  4. 같은 조건 비교: 같은 seed·장면·입력·카메라·뷰포트에서 변경 전후를 확인한다.
  5. 대표 흐름: 정상 부팅뿐 아니라 직접 링크·뒤로/앞으로·닫기·재열기·F5·취소·거부, 모바일 실제 크기와 혼잡 전투를 확인한다.
  6. 짧은 기록: 확인한 화면·입력·조건, 남은 오해와 미검증 기기를 적는다.

정지 스크린샷은 배치·대비를, 실제 조작이나 짧은 녹화는 시점·상태 전환을 확인한다. 회색조·효과 축소는 보조 검사이며 실제 기기 검증 전체를 대체하지 않는다.

합리적인 대표 E2E로 충분하다. 같은 의미를 반복하는 테스트 조합이나 과잉 문서를 늘리지 않는다. 위험한 상태 경계와 사용자가 지적한 흐름을 우선한다. 문서 확인과 게임 기능 검증은 각각 실제 확인 범위로 보고한다.

기술 계약은 개발 규칙, 테스트 범위·완료 보고는 프로젝트 관리, 자동 탐지는 예약 QA에서 관리한다. 시안과 이 문서는 런타임 기능의 적용·검증 완료를 뜻하지 않는다.

13.빠른 리뷰 · 완료 체크리스트

  • □ P1 직접 URL·메인 복귀·뒤로/앞으로·F5가 실제 화면과 일치한다.
  • □ P2 조회/구매/소모를 분리하고 잠긴 조건을 읽는다. 닫기/재열기에서 포커스·스크롤·입력과 실행 수명이 맞는다.
  • □ P3 높이·투영·시간이 공통이며 숫자가 시각 명중점에 붙고 연타 리듬이 남는다.
  • □ P4 390px 실제 크기에서 시작·조작·확정을 읽는다. hover 없이 조회하고 버전·비차단 사망 안내를 확인한다.
  • □ P5 표시값이 최종 효과이며 확률·비용·다음 효과가 예측 가능하다. 언어 전환이 상태·스크롤을 보존한다.
  • □ P6 A+B 모두 필요, 조건 n/N, 개별 충족선·선택 경로와 교차/합류를 구별한다. 기존 프리뷰를 유지한다.
  • □ P7 장식보다 대상·위협·행동이 먼저 읽힌다. 군중전과 효과 축소에서도 아군·공격 경계를 구별한다.
  • □ P8 예고→준비→발사→명중→회복이 실제 사건과 맞고 이동·조준·회피를 색 이외로 구별한다.
  • □ P9 드롭→흡인→도착→확정, 합성 성공/실패, 해금·장착이 실제 변화와 일치한다.
  • □ P10 실제 공통 시뮬/렌더의 격리 시연이며 저장 불변·자동 재생·반복·소리 선택·직접 플레이가 확인된다.
  • □ 기존 레퍼런스와 같은 primitive 시안, 실제 화면·핵심 흐름의 대표 검증 근거와 미검증 범위를 기록한다.

기능이 없는 항목은 해당 없음으로 표시한다. 게임별 시간·수치·슬롯 수를 공통 기본값으로 복사하지 않는다.

기존 HTML Preview는 공개 저장소의 해당 ref HTML을 연다. 병합 전 리뷰는 main을 PR head의 commit SHA로 바꾼 링크를 사용한다. main 링크는 병합 전에는 기존 본문을 보여 준다. 빌드나 새 호스팅 서비스는 추가하지 않는다.

파일을 내려받아 직접 열 수도 있다. HTML Preview에서도 관련 HTML 링크와 앵커를 확인한다. HTML Share 사용 설명서는 PC 서버에 파일을 업로드해 공유하는 별도 기존 경로도 설명한다. 이 저장소는 README의 HTML Preview 전달 방식을 계속 사용한다.

관련 실험은 표현을 고르는 자료이며 공통 규칙을 자동 적용하는 런타임이 아니다. 레퍼런스 목록에서 역할과 출처를 확인한다. 변경은 이 HTML에서 관리하고 프로젝트의 구체 수치·전투 계약은 해당 프로젝트에서 관리한다.
